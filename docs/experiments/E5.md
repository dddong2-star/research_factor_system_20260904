# E5：代表因子选群、群内等权

## 目的

检验“先用代表因子判断应启用哪个完整因子群，再在群内等权”是否优于只组合代表因子的 E1–E4。E5 运行时先把人数小于 3 的簇并入最近的足够大簇，再训练外层；外层训练加均匀 Softmax 负载均衡（系数 0.01）。E5 写入独立的 `e5_*` 目录，不修改 E1–E4 套件目录，但与它们共用步骤 3 的同一份聚类产物。步骤 3 仍是原始簇；合并只发生在 E5 内存和 E5 运行目录。

## 输入

- `step4 run --cluster-run`：步骤 3 写出的聚类运行目录，其中已包含完整因子群。
- 回测与训练参数由 `step4 run` 提供：`--top-n`、成本、`--rolling-window`、`--epochs`、`--random-state`。
- E5 不接受 `--factor-top-k`。

## 是否使用模型

使用一个与 E2 同逻辑的外层 `FactorRouter`：只使用每日四维市场特征为每个**合并后**的代表因子评分，不使用绩效分支。外层训练在 Rank-IC MSE 上附加均匀负载均衡：训练集平均 Softmax 贴近 `1/K'`，系数为 `0.01`。每日选择权重最高的代表因子所对应的簇，然后将该簇全部成员赋予 `1 / 群大小` 的等权。

人数小于 3 的簇、负载均衡系数与 E6 相同，均为固定行为，没有 CLI 参数。

## 与前级差异

相对 E4，E5 不使用市场—绩效融合、Gumbel Top-k 或换手惩罚。相对 E2，路由权重只用于硬 Top-1 选出一个完整因子群，不直接作为最终代表因子组合权重；最终 Alpha 使用被选群内的全部原始候选因子。E5 运行目录写出的 `factor_groups` 是合并后的群，不是步骤 3 原件。相对 E6，E5 仍是每日硬切一个群、群内等权，没有最短停留，也没有内层路由器。

## 产物

每次运行创建 `e5_<UTC时间>_<哈希>\`，主要文件为：

- `daily_factor_performance.parquet`、`behavior_features.parquet`、`clustering.json`
- `factor_groups.parquet`、`factor_groups.json`
- `factor_groups\cluster_XXX.json`
- `representative_weights.parquet`
- `selected_groups.parquet`
- `factor_weights.parquet`
- `model.pt`
- `alpha.parquet`、`daily.parquet`、`metrics.json`
- `config.json`、`e5_manifest.json`

```powershell
python -m research_pipeline step4 run `
  --cluster-run .\research_runs\cluster_<run_id> `
  --experiments E5
```

字段与用途见 [产物参考](../reference/artifacts.md)。
