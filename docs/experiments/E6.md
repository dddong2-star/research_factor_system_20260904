# E6：外层选群、内层动态路由

## 目的

在 E5 的因子群框架内，把群内等权替换为群内因子的动态市场—绩效融合权重，形成两级层次化 MoE。过小簇合并与外层均匀负载均衡与 E5 相同。外层不再每日硬切一个群，而是主簇最短停留 20 个交易日后才切换；当前关掉 Top-2，每天只用主簇。

## 输入

与 [E5](E5.md) 相同：读取 `--cluster-run`，不再自行聚类。完整命令和默认值见 [命令参考](../COMMANDS.md#step4-run)。步骤 3 仍使用原始簇；E5 与 E6 都在运行时合并过小簇，合并结果只写进各自运行目录。

## 是否使用模型

使用 `1 + K'` 个 `FactorRouter`，其中 `K'` 为合并过小簇之后的簇数：

- 运行时把 `group_size < 3` 的簇并入中心距离最近、且人数不少于 3 的簇；若当时全是过小簇，则反复合并最近的两簇，直到只剩一簇或都达到 3 人。被并入后沿用目标簇原代表因子，簇编号压缩为 `0 .. K'-1`。
- 一个外层模型仅使用市场特征，对**合并后**的代表因子做 Softmax。
- 外层训练在 Rank-IC MSE 上附加均匀负载均衡：训练集平均 Softmax 贴近 `1/K'`，系数为 `0.01`。内层不使用该系数。
- 主簇按外层权重选择，但必须在日期轴上停留 **20 个交易日** 后才允许切换；未满停留天数时忽略瞬时最优。
- 当前 `soft_top_k=1`：每天只用主簇，`group_weight` 固定为 1，不混合第二簇。
- 每个合并后的簇各有一个内层模型，同时使用市场特征和群内因子的 9 维滚动绩效特征。
- 每个内层模型在全部训练日期上训练，不仅限于该簇曾被外层选中的日期。
- 被激活的主簇内全部因子经稠密 Softmax 得到内层权重；未激活簇权重为零。

内层随机种子为 `random_state + cluster_id + 1`。最短停留 20 日、只用主簇、最小簇人数 3、外层负载均衡 0.01 均为 E6 固定行为，没有 CLI 参数。

## 与前级差异

相对 E5，E6 取消每日硬 Top-1 和群内等权：主簇有 20 日最短停留，每天只开这一簇；群内改为每簇独立的融合路由器。过小簇合并与外层均匀负载均衡 0.01 现已与 E5 相同。它没有 E4 的 Gumbel Top-k 和换手惩罚，也不使用 `--factor-top-k`。当前不混合第二簇。E6 运行目录写出的 `factor_groups` 是合并后的群，不是步骤 3 原件。

## 产物

每次运行创建 `e6_<UTC时间>_<哈希>\`，主要文件为：

- `daily_factor_performance.parquet`、`behavior_features.parquet`、`clustering.json`
- `factor_groups.parquet`、`factor_groups.json`
- `factor_groups\cluster_XXX.json`
- `outer_representative_weights.parquet`
- `selected_groups.parquet`
- `inner_factor_weights.parquet`
- `factor_weights.parquet`
- `models\outer_router.pt`
- `models\inner\cluster_XXX.pt`
- `inner_router_configs.json`
- `alpha.parquet`、`daily.parquet`、`metrics.json`
- `config.json`、`e6_manifest.json`

```powershell
python -m research_pipeline step4 run `

  --experiments E6
```
